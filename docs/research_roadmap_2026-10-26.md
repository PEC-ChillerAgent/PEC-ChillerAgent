# 冷水机组项目研究建议与改进路线

日期：2026-10-26。依据：当前项目源码、说明、历史结果和本轮数据核查。用户已确认，目前只有项目中的 ASHRAE 数据，尚无真实现场数据。

范围更新：用户随后明确，当前保留的主体是 `chiller_app`，它以 Buildings ElectricEIR 方程移植为基础，其他训练代码和历史产物可能已停用。因此，本文的历史数据审计不应解释为当前主应用的诊断指标。当前优先研究方案已调整，见 [ElectricEIR 当前研究方案](electric_eir_research_plan.md)。下文保留为前一轮分析与数据条件参考。

本文是基于项目证据的研究设计，不是已经完成的系统文献综述；文中的创新点均为待验证设想。本轮没有修改应用算法、重新训练模型或生成新的诊断性能结论。

## 1. 建议研究方向

建议现阶段题目：**测点受限条件下基于健康基线残差与可靠性评估的冷水机组故障检测研究**。

核心问题：只有四个水温和机组功率、且其中部分测点可能缺失时，能否利用少量健康数据建立正常运行基线，在未见工况上维持可接受的误报率和故障检出率？当证据不足或工况超出训练范围时，模型能否明确表示无法可靠判断？

先完成“正常/异常检测”，再根据实验结果增加“候选故障定位”。贝叶斯网络是候选定位方法，不作为第一阶段必须实现的模块。获得现场数据后，再研究低频时间序列、虚拟流量和跨机组迁移。

当前不要把研究目标写成“已实现低频现场诊断”“已实现无流量 COP 精确估计”或“已完成跨机组泛化”。当前数据与验证不支撑这些表述。

## 3. 本轮核查：需要优先修正的证据问题

### 3.1 数据现状

实际核查 `artifacts/layered_clean.csv`：

- 11,000 行；标签 1 有 4,000 行，标签 2—8 各有 1,000 行。
- 可直接观测的核心量是 `TEI_K, TEO_K, TCI_K, TCO_K, P_W`。
- 没有真实时间戳、两侧流量或水泵频率；`run_id` 全部为 `default`。
- 以四个水温和功率的五维测量向量比较，有 409 行精确重复，得到 10,591 个唯一向量；健康样本中有 3,872 个唯一向量。
- 精确相同的五维测量向量未发现对应多个标签。
- 标签按大块排列，切换行位置为 0、4000、5000、6000、7000、8000、9000、10000。行序本身不是时间证据，不能把按行划分称作时间外推。

这些事实只适用于当前项目汇总表，不意味着完整 ASHRAE RP-1043 原始数据也没有额外测量和试验记录。

### 3.2 当前“外部验证”不能作为独立泛化证据

历史 `external_validation_test.json` 报告外部 40 行分类准确率 100%。本轮比较对应的 `external_validation_test.csv` 与 `layered_clean.csv`，40 行均能找到相同测量和标签。

比较时将功率换为 kW，计算四个 K 温度与功率构成的五维欧氏距离，以距离小于 `1e-6` 判为相同测量。这容纳 CSV 保存产生的浮点差异，各温度差不超过 `1e-6 K`，功率差不超过 `0.001 W`。

按分类器的 `train_test_split(test_size=0.2, random_state=42, stratify=label)` 复现划分，40 行中 33 行与训练记录相同。这里是依照现有源码与源数据复现，不是追踪历史模型训练日志。

因此，这组结果只能作为样例回放或接口检查，不能支撑独立外部测试、跨机组或跨现场泛化。它也不能作为 OpenModelica 数值验证的替代证据。

### 3.3 随机测试集包含重复测量

历史分类报告的准确率约 97.82%、Macro-F1 约 0.974，来自随机切分。本轮复现相同切分，2,200 条测试记录中有 124 条与训练记录近乎相同。

这说明随机切分指标存在乐观风险，并不说明全部分类能力都无效。必须重新建立不重叠的测试，并检查近邻工况造成的更广泛相关性。

### 3.4 功能验证与科学验证要区分

本轮运行 `python -m pytest -q -p no:cacheprovider tests`，32 项通过。这验证现有测试覆盖的公式、接口和行为，未验证现场诊断准确率。

项目文档和编译日志表明，OpenModelica 对照停在编译失败阶段，尚无成功仿真误差统计。`self_compare_report.json` 的零误差也不能单独证明与独立 Modelica 参考一致。

## 4. 老师四条路线如何选择

| 路线 | 适用前提 | 当前建议 |
|---|---|---|
| Gordon–Ng / ε-NTU / 机理残差 | 核实具体模型所需的冷量、温度、流量及参数约束；有可辨识的健康工况 | 作为重点阅读和候选基线；先做输入与可辨识性检查 |
| 虚拟流量、虚拟冷量 | 至少有额外独立信息，如一侧流量、泵曲线和运行信息、短期标定 | 当前不作为主结果；没有流量真值就无法验证真实流量误差 |
| 定性物理与离散贝叶斯网络 | 可解释残差、明确因果假设、可估计或说明来源的条件概率 | 可作第二阶段候选定位；缺失节点应边缘化，不应当作正常 |
| 故障仿真与迁移 / PINN | 可验证的故障机理模型、独立现场目标域或充分约束 | 后续扩展；当前优先级低 |

### 四点需要准确理解

**Gordon–Ng 不能一概表述为四温加功率即可无条件求出真实冷量。** 常见形式涉及冷负荷等信息；一些变体可在恒流或额外标定条件下改写。读论文时必须逐项列出观测量、固定假设、待估参数和标定数据，才能决定是否适配。当前随机森林健康基线也应如实称为统计基线，不能因为使用了温差就称作完整热力学模型。

**守恒方程不能凭空补齐所有流量。** 在稳态、忽略散热且功率测量边界合适时：

`m_c cp ΔT_c - m_e cp ΔT_e ≈ P`

两侧流量均未知时，每个工况只有一个独立关系，不能唯一求出两个未知流量。若额外假设两侧恒流，可跨工况估计固定参数，但仍需足够工况变化，并验证假设和参数不确定性。泵频率与流量成比例也有相似工况和管网条件限制。

**健康能量守恒不是故障专属特征。** 换热器结垢时，稳态机组仍可满足总体守恒。能量不平衡常反映测量误差、测点不同步、储热或计量边界不一致；不能把它单独当成结垢标签。若用守恒方程估计流量，再用同一方程的残差验证流量或诊断，会形成循环论证。

**模型复杂度不能替代可辨识性。** 四个水温和功率可能不足以唯一地区分结垢、冷却侧流量减少、冷却条件变差及制冷剂异常。ε-NTU 也需要热容流率和换热侧状态等信息；水侧四温并不自动决定真实 UA。PINN 加入同一条欠定守恒方程，不能保证恢复唯一物理量。

离散贝叶斯网络通常可简称 BN；DBN 常用于动态贝叶斯网络。当前没有可靠时间序列，第一阶段宜采用静态推理并明确术语。

## 5. 可以验证的三个研究假设

**H1：健康基线残差具有检测价值。** 只使用健康训练数据拟合正常运行关系，在预先固定的健康误报率下，可以检出部分故障。应报告各故障的检出率；发现某些类别不可检测也是有效结论。

**H2：显式处理缺测可提高可靠性。** 与训练集统计量填补加缺失指示的基线相比，按可用测点选择条件模型或融合可用残差，能在相同可用传感器和相同信息预算下改善检出率或减少错误判断。

**H3：工况适用范围和拒识具有实际价值。** 在未见温区和严重缺测下，给出“工况外推/证据不足”能够降低已接受预测中的错误率，并明确代价是覆盖率下降。必须同时报告风险和覆盖率，不能只删除难样本后报告更高准确率。

以上均需实验验证。健康残差、缺失处理和贝叶斯网络本身都有大量前人工作；论文贡献不能只写成算法组合。可能的贡献是系统化的传感器组合评估、缺测与工况偏移下的可靠性方法，以及可复现的不重叠验证协议。

## 6. 现阶段最小可行技术路线

`数据审计 → 不重叠划分 → 仅健康样本训练 → 条件预测残差 → 健康校准集定阈值 → 异常评分与证据不足提示 → 可选候选故障定位`

### 6.1 首先建立可信的数据划分

1. 保留原始文件、原始行号和标签来源；精确重复样本可去重，或将同组记录固定放在同一集合。去重数量应记录在报告中。
2. 若能找回原始试验编号和工况记录，优先按独立试验分组。当前 `run_id=default` 和 `sample_id` 不能替代真实试验编号。
3. 无法找回时，明确只能做当前实验数据上的工况留出；按入口温度等预先定义的工况区间留出，并检查留出集中各类别支持数。它是工况外推评估，不是跨设备评估。
4. 做健康训练集、健康校准集、最终测试集三方隔离。分组完成后再做填补、缩放、建模和阈值选择，所有估计只在对应训练或校准集合完成。
5. 若做候选故障定位，故障标签也要分开用于训练/验证/测试；纯健康异常检测的最终故障测试样本不能参与模型选择。
6. 原始与派生样本、重复测量、同工况近邻要尽可能保持在同一分组，并报告分组依据。随机去重切分可作基线，不能替代真正独立试验。

### 6.2 先训练健康条件预测模型

从标签 1 的健康样本开始。可先比较线性/岭回归与随机森林，用部分水温预测健康功率或另一个可观测温度。例如：

`r_P = P_measured - P_predicted_healthy(available temperatures)`

输入温度组合要做对照。把故障也会改变的冷却出水温度放进功率预测器，可能有助于正常工况表征，也可能吸收故障信号；必须比较包含与排除该量时的检测表现。

不能用全部健康与故障混合数据训练一个性能回归器，再把它称为健康基线。现有性能训练入口没有自动筛选正常样本，需要新增明确的训练任务。

对不同可用测点组合可训练少量条件子模型。若功率缺失，功率残差不可用，应切换到其他已验证的温度关系或返回证据不足；不能以预测功率代替功率真值后继续计算同一残差。

### 6.3 校准异常分数与可信度

- 用独立健康校准集确定阈值，例如固定 5% 的目标误报率；同时报告测试集实际误报率及置信区间。
- 多残差融合要对最终融合分数校准，避免逐个残差各设 5% 后整体误报失控。
- 对残差的尺度和区间考虑工况依赖与测量噪声；样本不足时不能宣称精确条件覆盖。
- 检查观测工况是否超出训练范围；外推时输出标记或拒识。
- 已有随机森林 `predict_proba` 是模型分数，未经校准不能等同于真实故障概率。
- 只在被测量和有独立约束的量上计算可核验指标；模型估算值应始终带来源和不确定性。

### 6.4 故障定位以实验可分性为前提

第一阶段先输出正常、异常、证据不足。第二阶段再比较直接分类与基于残差的候选故障分类。

若引入 BN，可使用工况、缺测状态、残差定性状态和候选故障节点。离散边界、先验和条件概率须说明来自健康校准集、故障训练集还是专家设定，并做敏感性分析。缺测证据通过边缘化处理；残差之间可能共享传感器，不应假设完全独立而重复计数证据。

候选原因之间仍难区分时，输出候选集合及建议补测，例如冷凝侧实际流量或压力。不能把实验数据中的类别判别自动解释为已辨识真实结垢热阻或制冷剂充注量。

## 7. 用现有数据可以做的实验

| 实验维度 | 建议设置 | 必须说明的边界 |
|---|---|---|
| 完整测点 | 四水温加功率 | 作为所有方法的参考上限；信息量不同不能直接称算法优劣 |
| 固定测点减少 | 分别移除某个温度、功率，或预先选定多测点组合 | 是测点受限实验，可直接开展 |
| 随机测量缺失 | 10%、30%、50%，重复掩码与随机种子 | 是人为缺测压力测试，不等于现场真实缺失分布 |
| 工况相关缺失 | 在预定温区等条件下设置缺失 | 分析非均匀缺失；不能声称已覆盖全部缺失机制 |
| 健康训练样本减少 | 如 50、100、300、1000 条，在分组内抽样并重复 | 校准集保持独立，报告小样本波动和实际独立工况数 |
| 未见工况 | 按入口温度区间或恢复的试验工况留出 | 检查训练支持和类别覆盖；不要称跨机组迁移 |
| 人工测量偏置与噪声 | 温度偏置、功率比例误差；幅度按仪表精度或明确压力测试假设设定 | 这是测量扰动，不是机制验证过的结垢或充注故障 |

目前不能做真实 1/5/15/30 分钟降采样、动态报警延迟或连续掉线时长实验，因为汇总表没有可靠时间轴。随机减少行数测的是样本量，不能叫低采样率研究。不能在当前行序上计算 CUSUM 并解释为真实时间告警。

### 对照方法

至少保留：现有 RF 八分类；相同测点和划分下的填补加缺失指示分类器；健康 One-Class SVM 或 Isolation Forest；健康条件预测残差；提出的残差融合与可靠性方法。复杂模型数量应控制，先完成一个可复现主实验。

监督分类方法使用了故障标签，健康检测方法只用健康数据，两者训练信息不同，应分别报告其设定；不能用结果高低直接证明某方法全面优越。

### 指标

- 异常检测：AUROC、AUPRC、健康误报率、固定健康误报率下各故障检出率；明确类别比例。
- 故障定位：Macro-F1、逐类召回率、混淆矩阵、候选集合命中率。
- 可靠性：拒识率、预测覆盖率、已接受预测的错误率；若输出概率，报告 Brier 分数或校准误差。
- 回归：MAE、RMSE、偏差、区间覆盖率，并按健康/故障和工况分别解释。
- 重复实验：固定分组与划分清单，多个种子；有试验组时按组估计不确定性，不能把相关采样行当作完全独立样本。

### 消融实验

比较移除健康样本筛选、工况适用范围判断、缺测适配、残差融合和拒识机制后的变化。所有消融应使用相同测试集、传感器预算和阈值校准规则。

| P1 | 统一残差、阈值与可靠性报告 | 新增 `diagnosis/residuals.py`、`diagnosis/reliability.py` | 输出异常分数、阈值来源、适用范围和拒识原因 |
| P1 | 可复现批量研究流程 | 新增 `research/run_experiments.py` | 一次配置生成对照表、缺测曲线与消融结果 |
| P2 | 候选故障定位，必要时用 BN | 新增 `diagnosis/bayesian.py` | 缺测可推理，概率经过检验，不强迫唯一故障 |
| P2 | 网页增加研究结果展示 | `api/`、`web/` | 展示数据版本、适用范围和证据；不用堆更多输入表单 |
| P3 | 有新数据后开发虚拟传感器与故障机理仿真 | 新模块 | 用独立流量/冷量测量或故障实验验证 |

已有代码还应注意：

1. `clean_measurements` 的去重键包含默认生成的 `sample_id`，不能识别相同测量的重复样本；研究审计应另行定义重复关系，不能假定当前“去重 0 行”意味着无重复。
2. 统一当前工作台与旧诊断路径的能量平衡分母、阈值和适用工况；动态储热期间不能套用稳态故障阈值。
3. `temperature_lift_K = TCO - TEO` 是水侧温差代理量，不是实测制冷剂冷凝/蒸发饱和温差；特征说明应准确。
4. 校准的拟合误差不是独立预测误差。动态热容校准需要真实时间、流量和足够动态激励，不能用无时间汇总表验证。
5. 仿真模块、健康参考模型和诊断模块分清用途。ElectricEIR 曲线扰动可做假设性压力测试，但不能直接标为已验证的结垢率或制冷剂缺失百分比。
6. 本轮还复现了不支持扩展名上传返回 HTTP 500：`workbench.py` 上传分支引用未定义的 `field/numeric/invalid`，应修为明确输入错误并增加针对性检查。这是独立的接口问题，不影响上述研究方向判断；本轮未改动它。

## 9. 建议的六周顺序

| 时间 | 任务 | 可交付结果 |
|---|---|---|
| 第 1 周 | 文献输入条件表、标签来源核实、数据审计与分组 | 文献比较表、数据卡、不可做事项清单 |
| 第 2 周 | 冻结划分，重做 RF 与健康异常检测基线 | 无重叠基线结果及历史指标差异解释 |
| 第 3 周 | 健康残差、小样本实验、工况留出 | 固定误报率下各故障检出率 |
| 第 4 周 | 缺测适配、传感器组合和可靠性评估 | 测点预算—检出率曲线、风险—覆盖率曲线 |
| 第 5 周 | 重复实验、消融、候选故障定位可行性检查 | 有置信范围的主结果和失败案例 |
| 第 6 周 | 汇总贡献、局限与补测需求 | 研究报告/论文初稿及可复现实验配置 |

若找不回真实试验分组，应在第 1 周明确限制，并把结论控制在当前汇总数据的测点与工况实验范围。后续找回原始动态记录是扩展低频研究的优先动作，不要通过伪造时间戳补齐证据。

## 10. 文献应该怎么读

优先读四类：Gordon–Ng 原始模型及无流量变体；ASHRAE RP-1043 的原始试验与标签说明；冷机健康基线残差与少传感器故障诊断；缺失证据 BN、模型校准和分布外拒识。虚拟传感器与故障仿真迁移放在第二轮。

每篇记录：测点、是否有流量真值、标签与故障程度、健康样本量、时间频率、工况覆盖、划分单位、是否独立现场测试、指标和限制。这样才能判断前人的结果能否迁移到本项目，而不是只对比模型名称或准确率。

本轮没有逐篇联网检索和核验论文，故不提供未经核对的作者年份、DOI 或“首次提出”声明。开题前应把这张证据表补全，并据此收缩或修改贡献表述。

## 11. 可以向老师表述的设想

目前项目已具备数据接入、性能仿真和实验数据分类基础，但现有汇总数据缺少真实时间轴和流量，原外部样例与源数据重叠。因此先研究测点受限条件下的健康基线异常检测：使用正常工况拟合基线，以残差描述偏离，在严格隔离的数据上评估小样本、测点缺失和未见工况的影响，同时引入证据不足提示。检验哪些故障可以检出、哪些只能给候选原因，并据此提出最有价值的补测需求。取得独立现场或动态数据后，再验证低频采样、虚拟传感器和跨机组迁移。
