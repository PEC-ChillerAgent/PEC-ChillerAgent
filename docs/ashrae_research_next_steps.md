# ASHRAE 原始数据核查与下一步研究

日期：2026-10-26。研究主体为 `chiller_app` 的 Buildings ElectricEIR 前后端。此次只读原始数据、核对模型与配置并更新研究文档，没有修改应用模型。旧分类器的准确率不代表当前应用效果。

## 建议收敛的研究问题

建议方向：**稀疏测量条件下，基于正常性能模型与虚拟传感的冷水机组异常检测**。

可进一步收窄题目为：**基于 ElectricEIR 少参数校准的冷水机组稀疏观测可辨识性与异常检测研究**。

核心问题不是“能否把模型运行出来”，而是：只有水温与电功率、流量缺失和采样稀疏时，哪些性能偏离仍可识别？模型校准与虚拟流量是否会把故障吸收成参数变化？何时需要输出不确定或拒绝定位？目前没有独立现场数据，论文结论应限定为 RP-1043 实验数据上的受控稀疏观测研究。

## 原始数据改变了可做的实验

目录：`H:\a研究生\ASHRAE RP-1043(1)\Chiller Data`。

原始 `.xls` 中有 59 个实验工作簿和一个 `read me first.xls`。当前解析器成功读取 58 个实验工作簿，合计 Complete 299,194 行、Reduced Data Set 25,127 行、Steady States 1,559 行。`Benchmark Tests\near normal1.xls` 遇到 xlrd 记录解析错误，暂未纳入统计；不能仅据此判断文件损坏。其他 `.xlsx`、CSV 和脚本可能是后续加工产物，不能与原始实验混为同一层级。

Complete 通常为约 10 秒间隔，Reduced 通常为约 2 分钟，后者时间数值以分钟记录。原始完整数据含进出水温度、FWE/FWC 水流量、功率及制冷剂侧部分量，足以设计“保留测量参考、向算法隐藏测点、降低频率”的实验。此前五列汇总没有这些列，并不代表原始数据也没有。

数据使用前须确认：

- 原始温度为 °F。FWE/FWC 有强证据为美制 gpm：与冷量及温差的换算近乎吻合。导入应保留原值和换算依据；1 US gpm = 0.22712470704 m³/h。压力表压/绝压口径尚未证实，暂不用于需要绝压的物性推算。
- 冷量与 COP 多为由流量、温差和功率派生的量，并非独立测量真值。虚拟流量应对照原始流量测点；不能再把隐藏流量派生的冷量/COP作为输入。用同一公式算出的能量闭合也不构成独立验证。
- `Unit Status` 为多值状态码，不能直接按非零视为正常开机；`Active Fault` 是机组内置故障/报警码，不能直接替代实验注入故障标签。
- 部分时间戳重复/非递增，存在中止实验后的填充或重复数据及极端功率值。记录清洗规则、排除数量、原文件与原行号，不能直接随机打散全部行。
- readme 明确 `normal1` 是 reference standard。不同正常实验存在控制程序、油量、试验顺序等差异，需要按实验历史匹配基线。
- 故障严重度必须按原实验定义。例如 `cf12` 指冷凝器 164 根管中堵塞 20 根（约 12.2%），不能写成“污垢热阻增加 12%”。部分试验未达稳态或中止，需按 readme 排除或单独研究。

## 依次完成的研究实验

### 1. 数据基准与数值对照

建立独立于网页的数据导入流程：显式选择 Complete/Reduced/Steady sheet，统一单位，记录数据质量和实验说明。先用正常稳态工况开展研究，再进入动态与启停段，避免同时处理模型迁移、瞬态初值和故障。

同时完成项目已有 Modelica 对照：同一参数、物性、输入、初态、启停和输出时刻下比较 Python 与 OpenModelica。项目现有 32 项测试曾通过，但成功的原始 Modelica 数值对照仍需完成。方程移植一致性与真实设备适配性分别验证。

### 2. 正常模型校准与可辨识性

使用健康训练文件选择参考曲线、拟合少数参数；健康验证文件确定超参数和误报阈值；最终健康与故障测试文件冻结使用。按文件、试验日期或完整连续工况段分组，不能把相邻样本随机分到训练测试两边。基线组之间有程序/工况差异，先核实可比性，再决定具体文件划分。

先尝试一个功率修正参数，再按证据增加参数。不要同时拟合额定容量、COP、全套曲线、两侧流量和热容。多初值拟合、局部灵敏度与参数相关性用于检查“不同参数能否得到几乎相同输出”。参数在健康期校准后冻结，不在每个故障点重新自由拟合。

比较至少三个正常功率基线：当前默认 EIR、少参数校准 EIR、相同可见输入下的简单回归；数据与条件允许时加入 Gordon–Ng 基线。EIR 是性能曲线模型，不能直接称为 Gordon–Ng。ε-NTU 需要额外的换热与工况信息，应先明确其参数能否被现有数据辨识。只有独立测试效果与解释性确有改善，才能主张加入物理模型有价值。

### 3. 受控稀疏观测与虚拟传感

建议设置嵌套实验：

| 情境 | 算法可见信息 | 用途 |
|---|---|---|
| 完整水侧 | 四个水温、功率、两侧实测流量及必要控制量 | 参考上限与正常模型适配 |
| 隐藏单侧流量 | 四个水温、功率、另一侧流量及必要控制量 | 检查单侧软测量 |
| 隐藏两侧流量 | 四个水温、功率及必要控制量 | 研究欠定性与估计区间 |

制冷剂侧内部量首先全部从算法输入中移除，可另作参考分析。每种情境比较原始约 10 秒及 1/5/15 分钟抽样；分清直接抽点与窗口平均，两者并不等价。加入缺失片段与合理噪声是后续扩展，不必第一轮同时叠加所有干扰。

表中列出的是可获取的测点，实际模型输入必须按任务再限定：功率预测和功率残差模型不能把同一时刻的实测功率作为预测输入；实测功率可作为残差的比较对象，或在独立定义的虚拟流量逆问题中作为观测。功率参与反演后，不能再用其拟合残差冒充独立异常证据。温差接近零时，流量反演对噪声高度敏感，应报告区间或不输出点估计。

在“两侧流量未知”情境中，能量守恒只提供流量组合约束，不能唯一给出两个流量。若通过 EIR 健康假设反演，需要把假设和区间写清楚：故障可能改变模型关系，导致虚拟流量偏差。虚拟量能否提升异常检测必须独立检验，不能因为公式带物理量就假定准确。

分别报告健康校准允许用哪些传感器、部署时可见哪些传感器。利用完整传感器标定后部署和从始至终只有稀疏传感器，是两种成本与信息条件不同的实验，不应混报。

### 4. 残差检测，然后才做定位

以健康模型预测功率、可预测温度或虚拟量为基础，构造残差并按负荷/温度工况归一化；只用独立健康验证集确定阈值。首先回答“能否识别异常”，再比较残差是否足以区分不同故障。流量下降、结垢、充注偏离可能产生相似残差，不能仅凭一个功率偏差强制给出唯一原因。

评价包括功率/温度预测误差、虚拟流量误差、健康误报率、各故障类型与严重度的检出率及不确定区间。按文件或试验组统计/重采样，避免用高度相关的行虚增独立样本数。异常概率与置信区间若要展示，需要实际校准与覆盖率检验。

原始故障往往是预先设置的实验条件；没有可靠发生时间就不报告在线检测延迟。不在健康和故障文件之间拼接一个虚构发生时刻当成真实在线故障。更不能把全部故障样本校准进“正常模型”。

## 老师四条路线如何安排

近期主线是正常性能基线、少参数校准和残差分析，配合虚拟传感及可辨识性实验。先阅读 Buildings 源码所引 Hydeman 与 Gillespie (2002), *Tools and Techniques to Calibrate Electric Chiller Component Models*（ASHRAE AC-02-9-1），再查证 Gordon–Ng 在相同可见输入下的假设与适用性；目前只核对了前者的源码引用，尚未全文审读。

贝叶斯网络放在残差可解释、不同故障确有区分信息之后，先做故障候选概率与“证据不足”，并区分离散贝叶斯网络与动态贝叶斯网络。不能仅凭术语 DBN 判断是否含时间结构。

TRNSYS/EnergyPlus 迁移暂不作为首要工作：当前没有独立真实现场目标域；同一 RP-1043 的降采样研究也不能直接宣称跨现场迁移。PINN 同样放后面：守恒约束不能自动补足不可辨识信息。现有 ElectricEIR 缺少制冷剂充注量、污垢热阻、压力状态等显式机制，改变曲线系数产生的是假设的性能扰动，不是已经验证的真实故障数据。

## 应用改进顺序

1. **可追溯导入与导出**：支持 workbook sheet 选择、°F/gpm 显式单位、时间单位和实验段标识；记录原文件/原行、清洗原因。导出实际输入行、测量值、模拟值、单位、参数与模型版本，才能复现实验。
2. **机组适配与有效范围**：区分默认示例记录、真实目标机组和已校准记录；显示当前工况是否超曲线范围，汇总越界比例。允许保存健康数据校准版本和适用工况，避免把默认机组预测作为通用故障基线。
3. **测量与模拟比较**：并列显示实测/模拟功率与出口温度及残差；明确 t=0 是指定初态、是否用实测初始化及暖机段规则。仿真内部能量平衡误差只能检验数值一致性，不能当故障证据。
4. **实验工作台**：配置可见传感器、抽样间隔、冻结的参数与检测阈值；按文件评估并导出误差、误报和检出率。研究流程稳定后再接入网页。
5. **谨慎的诊断输出**：先给异常分数、适用范围及证据；定位证据不足时给候选原因，不直接生成结垢/欠充等确诊结论。

## 用户提供的运行配置说明

附件记录了恒定输入、动态模拟 3600 秒、输出间隔 60 秒和 61 行输出；这些是合成模拟点，不是 61 个 ASHRAE 实测样本。配置里没有实际那一行温度/流量数值，也没有实测功率或出口温度。`source` 是“手动输入”，目前不能复现某个 ASHRAE 工况。

字段名 `TEI_K` / `evap_flow_kg_s` 是内部标识；schema 已声明原始输入单位为 °C / m³/h，不能凭后缀认定单位输入错误。EIR 实际热容为 1,299,132 与 2,415,004.8 J/K，来自名义流量×30 秒×比热；配置中遗留的两个 20,000,000 J/K 和容量功率比 4 不代表本模式生效参数。初态为空时采用 5°C/25°C，初始冷冻出水低于默认曲线下限；这属于初始化/越界问题，不是结垢证据。
