# 现场手抄数据目标下的模型与代码审查

日期：2026-10-26。本文按用户澄清后的实际目标审查：现场人工抄录的稀疏数据输入，建立可解释模型，逐步替代目前以 Modelica Buildings ElectricEIR 方程为基础的应用计算。

## 先区分“替代”的两种含义

当前 `chiller_app` 做的是把 Buildings 13.0.0 的 ElectricEIR 水冷制冷模式方程移植到 Python。它可以成为不依赖 Modelica 运行时的同方程计算内核；这叫方程移植/数值替代，必须用 OpenModelica 同工况输出证明一致。它不是完整 Buildings 冷机系统，也没有压缩机循环、制冷剂状态、换热器污垢热阻或故障机理。

研究中另一种“替代”是利用现场手抄观测建立更贴合目标机组、输入测点更少的可解释近似模型。这不是通过逆向 ElectricEIR 自动得到的，需要用目标机组数据识别模型结构和参数，并与 ElectricEIR 和简单统计基线独立比较。建议论文目标明确为后者，同时先完成前者作为可靠起点。

## 当前实现做得比较完整的部分

- `chiller_app/model/electric_eir.py` 实现温度双二次曲线、PLR 二次曲线、平滑限幅、最低负荷循环、理想出水设定值控制、压缩机功率、冷凝热和两侧水温动态。实现没有假称为制冷剂循环求解器。
- 输入参数、曲线来源和 Buildings 源文件摘要进入元数据；UI/接口区分实测值与模型输出，也提示曲线外推。
- 32 项 Python/API 测试通过，覆盖能量方程、停机、负荷限值、初始化、动态与稳态、字段/单位、控制输入和 API 合同。
- 原 Buildings 方程与实际机组校准本来就是两种验证；当前文档对这一边界有说明。

## 不能称为已验证替代的地方

1. **OpenModelica 数值对照已补齐。**当前参考 CSV 和对照报告见 `tests/reference/` 与 `artifacts/eir_validation/`；验证范围限于所列参数和工况。
2. **现有输入假设与现场手抄表可能不相容。**ElectricEIR 强制要求两侧进水温度、两侧正流量、设定温度和启停状态。若现场手抄表通常没有流量计，这个版本无法直接运行；默认数值/额定流量代替实测流量会引入强假设，不能伪装成观测。
3. **模型范围仍较窄。**只针对一个 Buildings 类别的水冷制冷模式、正向非零流量和理想设定值控制；不等于实际冷站的完整机组、泵、塔、阀和控制系统。
4. **ElectricEIR 已有单参数校准。**`/model/electric-eir/calibrate` 只拟合健康稳态功率尺度，仍需独立数据验证和机组适配。
5. **已有随机森林不适合作为本研究的可解释替代基线。**`performance_model.py` 随机逐行拆分，且特征中含 TCO、两侧流量，可能与现场可用测点不符。时间相邻样本会泄漏到测试集；分别预测冷量、功率、TEO、COP也不保证热力学一致。不要把旧 artifacts 训练报告作为新主线证据。
6. **数据导入还不能无缝覆盖 ASHRAE 原表。**上传 Excel 默认只读第一个 sheet；应用 flow_unit 没有 US gpm。实验目录还需要明确 sheet、时间单位、状态码和实验段语义才能安全进入计算。

## 建议按优先级改进

### P0：把现有 Python 代码验证成可信的 ElectricEIR 移植

- 修好或绕过当前本机 OpenModelica 编译环境问题，产生可复现 reference CSV；保存编译器版本、库版本、命令、日志与源文件摘要。若 Windows MSYS 并行 make 造成映射错误，先在正常终端/串行编译或隔离构建目录验证，不要用自行生成的 Python 结果充当参考。
- 覆盖多个工况：额定、部分负荷、最低卸载、停机/重启、设定值阶跃、冷却进水阶跃、曲线温区边缘和超可用容量；动态比较事件前/事件右侧同一时刻。
- 各输出报告绝对/相对误差和容差，确认初值、时间步、状态方程、cp、水介质参数、流量边界一致。
- 将代码中不可避免的平台/求解器误差与公式差异分开；只有通过后称“已验证的 ElectricEIR Python 移植”。

### P1：把手抄数据变成可以审核的输入

- 定义最小数据表：日期时间或采样间隔、试验/机组 ID、冷冻水进出水、冷却水进出水、功率、设定温度、运行/负荷状态；每字段标记手抄、控制器读取、额定假设或计算派生。保留原始值、单位、来源和人工备注。
- 不能要求用户提供没有测到的值后默默填额定流量。若流量缺失，让 ElectricEIR 模式显式拒绝/标记需要假设；另提供“稀疏现场模型”入口并输出适用范围和置信区间。
- 表格解析支持 Excel sheet 选择、CSV/Excel 模板和单位显式选择。加入 gpm 支持或建立保留原始列的转换层。对 ASHRAE 先用 `Complete` 和 `Steady States` 的显式选择；`Unit Status` 需要经过状态码字典转换，不能直接作为 0/1。
- 生成数据质量报告：重复/逆序时间、跨试验混接、停机值、量纲/范围、稳定性、缺失比例和源行号。清理应可复现，不能无记录删行。

### P2：建立现场可用的可解释替代模型

先用完整 RP-1043 水侧数据做方法开发，再用手抄场景设定输入掩码。先冻结真实部署可用的少量变量，例如进出水温、功率、设定温度/负荷率；把流量、冷量和内部压力从输入中隐藏。再评价能否预测未直接测量的结果。

比较三个同样数据划分下的基线：

1. Buildings ElectricEIR 默认/少参数校准版本（机理方程基线）。
2. 低复杂度可解释回归，例如按负荷/温度分段的线性模型或受符号约束的回归（数据拟合基线）。
3. 建议的可解释灰箱：保留水侧 `Q=m cp ΔT` 和能量平衡，拟合少量功率/效率修正参数；必要时增加负荷、冷凝进水温度等低阶项。模型阶数由文件级独立测试选择。

避免随机拆分连续行。用不同运行段/实验文件分组留出；模型仅在训练健康样本校准，参数和阈值在验证组定好后冻结。以独立测试组报告功率/温度预测误差、偏差、区间覆盖率和超范围比例，并与只用均值/线性回归比较。热力学守恒是结构约束，不会凭空识别两个未知流量；信息不足时应给范围或拒绝作答。

### P3：逐步形成异常结论而非先堆诊断算法

先定量建立健康模型残差的正常波动，再对预先设定的 ASHRAE 故障工况验证能否检测。以文件/故障工况为单位报告误报和检出率。确认残差特征可区分后，才加入离散/动态贝叶斯网络解释候选原因。没有真实时间故障起点，不报告在线延迟；没有独立现场数据，不声称现场泛化。

## 建议的近期工作序列

**第一项：Modelica–Python 独立数值对照。**这是判断逆向移植是否完善的直接证据，先解决参考结果缺失。

**第二项：用 `normal1` 等 benchmark 做默认 EIR 检查和少参数校准。**前轮 27 个 `normal1` 稳态点的默认 McQuay 比较得到功率 MAE 14.28 kW、MAPE 26.4%，19/27 点在默认曲线温区外；这是未经校准的跨设备比较，只说明该默认参数不能直接当 RP-1043 健康基线。

**第三项：从 ASHRAE 完整测点模拟手抄稀疏输入。**保持完整值作为参考，分别隐藏流量/内部量，按 1、5、15 分钟间隔下采样；确定温度、功率和时间组合下的可预测边界。

**第四项：形成精简的可解释模型并文件级比较。**若低阶灰箱在独立文件上接近或优于校准 EIR，同时输入更贴合手抄表，再考虑把它设为应用主引擎。当前阶段不宜直接删除 EIR：它是用于机理基准和可比实验的参照实现。

**第五项：形成有限、可证据支持的结论。**先异常/正常二分类或性能偏离识别；再看数据是否足够区分结垢、流量降低、充注变化。对不能区分的类别，应用应输出“不确定/需补测流量或内部压力”，而不是编造唯一故障。

## 代码层建议的落地次序

1. 在 API/页面明确区分 `ElectricEIR移植仿真` 与 `现场稀疏数据模型`，并声明各自输入和验证范围。
2. 实现数据模板、工作表选择、gpm/°F、数据质量与实验分组导入。
3. 写独立 OpenModelica 对照自动化和容差报告；保留原测试做快速回归。
4. 新增只在健康训练数据上运行的 ElectricEIR 少参数校准与组间验证模块，严禁在测试集选 record/曲线。
5. 新增可解释的低阶替代模型并提供系数、输入贡献、适用域、预测区间和残差诊断。以跨文件验证决定是否替换默认入口。

当前不建议先加 PINN、深度迁移学习或更复杂 DBN：它们不解决缺失流量和传感器不可辨识的问题。

## 手抄数据场景中特别要补的设计

- 不同时间人工抄写的四个水温与功率可能不是同一瞬时工况。尽量记下同一轮读数的开始/结束时间、是否调节过设定值/水泵；不能把不同时间的读数当成精确同步能量平衡。功率要确认是压缩机/机组总电功率、瞬时 kW 还是累计电量 kWh，不能用电流直接等同 kW。
- 零散手抄记录以独立工况/近稳态评估为主，记录之间的间隔不是“上一行工况持续至下一行”的证据。当前动态模式采用零阶保持，长间隔下会自行补出未观测的中间过程；除非有连续运行和控制记录支持，不应把该过程当成现场实际瞬态。
- 约 30 秒水侧时间常数对应的动态信息可能早于 5/15 分钟采样点消失，因此不宜直接凭稀疏手抄表拟合 tau/热容。先用高频原始序列判断可辨识程度，再决定是否保留动态参数。
- 误差评价先定义预测任务：预测功率时输入不能含同一时刻的实测功率；若功率用于反演流量，则不能再拿这一路功率重构残差当成独立异常证据。温度已作为输入时，不能把重现同一温度当作预测成功。
- 输出解释包括输入证据、假设、适用工况、参数含义与预测区间。低阶多项式的系数可读不等于每个系数都对应唯一物理原因；仍需灵敏度与独立实验支持。

## 性能优化应在数值对照通过之后进行

当前实现逐行 `iterrows`、逐字段 `.loc` 写回，并在每个采样区间启动一次 BDF。大量数据时这些操作可能比曲线计算本身更耗时。先记录 27 个稳态点和数千时序点的耗时作为基准，再考虑将输入转为数组、统一收集输出后构造 DataFrame，避免重复计算同一状态的负荷；这些优化应保持原有事件、初始化和零阶保持语义。

冷凝侧在已知热源轨迹时是线性方程，可研究解析积分或专用积分，但热源仍受蒸发出水状态影响，不能未经证明把整个动态模型替换成两条独立指数解。对手抄稳态任务，优先使用已经存在的稳态求根，通常比降低 BDF 精度更合适。优化前后需用相同参考工况比较误差与时间，不先承诺加速倍数。
