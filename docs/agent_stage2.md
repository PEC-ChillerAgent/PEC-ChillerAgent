## 配置模型

打开聊天页的“模型连接配置”，填写服务商提供的 Base URL、已开通的模型名和 API Key，点击“保存配置”再“测试连接”。Base URL 使用服务商的兼容聊天 API 前缀，客户端自动追加 `/chat/completions`；也可粘贴完整聊天地址，保存时会去掉该后缀。

服务与模型需支持 OpenAI 兼容的 Chat Completions 和 function calling。当前采用非流式请求。厂商特有参数可填入高级 JSON，例如对应服务要求的 thinking 参数；仅填写该模型官方文档支持的字段。高级参数不能覆盖消息、模型和工具定义。

API Key 仅提交到本地后端，页面不会回显，浏览器不把密钥存入 localStorage。页面保存的密钥位于本机 `outputs/energy_agent/agent.sqlite3`，属于明文服务配置，并未做加密保险库处理。不要将数据库提交或分享。保存时留空会在地址相同的情况下保留密钥；更换地址须重新填写密钥。

也可在**启动服务的同一 PowerShell 进程**设置：

```powershell
$env:ENERGY_AGENT_LLM_BASE_URL = "https://服务商的兼容地址/v1"
$env:ENERGY_AGENT_LLM_MODEL = "已开通的模型名"
$env:ENERGY_AGENT_LLM_API_KEY = "本地填写你的密钥"
```

`ENERGY_AGENT_LLM_*` 环境变量覆盖页面保存的对应项，页面会显示覆盖提示；保存页面配置不会改变进程环境。通用 `OPENAI_API_KEY` 仅在目标主机恰为 `api.openai.com` 且没有专属或本地密钥时回退使用，不自动用于第三方服务。`.env.example` 是说明模板，应用不会自动加载 `.env`。

## 开始设备分析

1. 打开原工作台，输入工况或上传文件，检查字段映射、源单位和物性；需要仿真时选定匹配的机组参数与运行模式。
2. 点击“转入智能分析”。页面将当前数据登记为持久数据集，并带入资产 ID、单位、物性和当前仿真设置。
3. 在聊天页提出问题，例如“计算这批数据的实测制冷量和COP，并说明缺测情况”。对比和仿真需显式勾选模型设置；模型不能猜测机组型号。
4. 查看“工具调用与计算证据”，点击数值核对完整 JSON，或下载 Markdown 报告。

也可在聊天页直接选择已登记数据集。会话创建后固定数据集、设备和仿真配置；更换数据或设定值请新建会话。历史会话重启后仍可读取。

未绑定数据的一般知识问答可使用解释性数字，并明确标注不是当前机组计算结果。有设备绑定或工具调用时，数值须通过服务器事实引用；不合规回答会受限修正，仍失败则显示已完成工具的事实报告。事实片段显示指标名称、来源与单位。对显式实测/模型或指标类别错配进行检查，但这不证明任意自然语言解释都正确。

正文中回显的已绑定数据集、机组及有证据的运行编号，会转换为“当前数据集”“当前机组”“该分析运行”。带省略号的数据集/运行编号只在十六进制前缀至少八位、且唯一匹配已知引用时转换；未知编号和未经事实引用的数值仍会触发校验。历史对话保留当时保存的结果，不会因规则更新而自动重写。

定性解释中的“为零/不为零”只在本答案已经引用该指标、能够唯一匹配事实且判断与事实值一致时，转换为对应事实引用。未知、歧义和与事实矛盾的判断仍会拒绝；“单一”“百分比”等非数量用语不单独视为测量数值。修正请求会指出触发校验的具体数字，避免模型反复修改无关文字。

## 与原网页计算的关系

聊天模型理解问题并选择 `inspect_dataset` 或 `chiller_analyze`。后者继续通过 `energy_agent/tools/chiller/backend.py` 调用 `chiller_app.api.workbench.run_workbench`，原工作台也调用这个函数。底层水侧方程和 ElectricEIR 求解器相同。

“转入智能分析”登记的是原始记录、源单位、物性和所选仿真设置，聊天按需重新执行工具，没有直接复用工作台上一次的结果。工作台顶部卡片显示末条记录或末时刻，聊天工具指标显示有效输出点均值；比较时需使用相同数据、设置和汇总口径。

示例物性为 cp=4180、密度=1000 时，示例实测 COP 为4.18；工作台默认 cp=4184、密度=995.586 时，同一表面工况约为4.1655318。转入聊天会保留生效物性，比较结果时应核对它们。

每轮最多4次模型请求、4次工具调用。缺配置、鉴权、限流、超时和缺测会明确显示；没有自动付费重试。同一会话发送过程中禁止重复提交，服务端同时用 SQLite 租约拒绝并发。

## 验证范围

当前本地验收使用明确标识的兼容协议测试服务；物理工具实际运行。`outputs/stage2_provider_protocol_smoke_test.json` 与测试截图中的模型回复来自 fixture，不能作为真实厂商验收依据。测试专用 `8769/8770` 端口及 `outputs/stage2_ui_fixture` 数据库与正常服务分开。生产没有自动替代的假模型。

真实厂商调用需在本地填写实际地址、模型和密钥后，执行连接测试及一轮工具分析。2026-10-29已使用用户本地保存的DeepSeek配置查询真实模型列表，并以`deepseek-flash`通过连接测试（HTTP200、“连接成功”）；这项检查不代表已经验收真实模型的设备工具分析。

DeepSeek配置示例：Base URL为`https://api.deepseek.com`，模型名为`deepseek-flash`（或当前账户可用的其他模型ID），不能只填服务商名称`deepseek`。模型ID以服务商当前`/models`接口和官方文档为准。排查时发现Codex受限执行环境注入的代理指向不可用的本地端口，因此正式服务已从允许联网的环境重启；正常使用时可从用户自己的PowerShell启动，无需修改程序或关闭系统代理。

后续可在同一注册表增加水泵、冷却塔、中央空调系统工具；本阶段未实现这些数值模型、现场控制、多用户鉴权或流式输出。
